# DSI-Wiki — audit and cleanup (2026-08-06)

A full scan of this project as part of a host-wide sweep across the three foundational projects
(DSI-Wiki, DSI-Database, DSI-LLM-Router). Purpose: confirm the CLI tools/skills that are wired
into this host actually work against the current live deployment, find and remove stale paths
left over from this host's several directory reorganizations (`~/READY` → `~/CLEANUP` →
`~/BASE` → `/BIG/PROJECTS/DSI`), and record the result somewhere durable.

## What was checked

- Every `CODE/` module that reads a filesystem path from an environment variable, to confirm the
  variable it reads actually exists in the real `SERVICES/.env` and that a missing variable
  fails loudly instead of silently falling back to a stale host path.
- Every `TOOLS/*.py` / `TOOLS/*.sh` script, for the same class of stale-path bug, plus whether
  each script referenced in `TOOLS/install-cli-proxies.sh` actually produces a working
  `~/.local/bin/DSI-wiki-*` proxy.
- Every `SKILLS/*/SKILL.md`, for accuracy against the real current access mechanism (Docker CLI
  proxy, not direct Python import) and real current paths.
- `JSONS/DSI-Wiki-Multi-Server-Config.json`'s `default_base_dir`, which `DSI-Wiki-Ingest-Service-
  Class.py` reads live as the fallback base directory when no explicit route matches a raw note.
- The real host filesystem for debris left behind by the stale-path bugs above (a script writing
  to the wrong, now-uninhabited old directory tree leaves files there that never get cleaned up
  by anything, since nothing reads that tree anymore either).

## Known-still-broken, deliberately left as-is

- `TOOLS/wiki_morning_refresh.py`'s `create_tasks()` step imports
  `databases.dispatcher.db.DSIDatabase` from a path (`~/READY/DSI-Database`) that no longer

  broken-but-documented rather than fixed blind; it needs to be re-pointed at DSI-Dispatcher++'s
  `CODE/dispatcher_core/db.py` once someone actually re-enables this script, not guessed at now.
