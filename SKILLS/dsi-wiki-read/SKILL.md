# DSI Wiki Read (get / topics / search)

Internal consumers (Claude sessions, dispatcher tasks, services, workers) read the wiki with
these CLIs instead of `mcp__llm-wiki__*` calls — no MCP round-trip, no HTTP client needed. On
this host's Docker deployment, each wrapper proxies into the running `gateway` container
(`docker compose exec`, read-only mount — see `TOOLS/install-cli-proxies.sh`), which in turn
runs the real `SKILLS/cli/*.py` scripts against the served `Wiki-BASE` tree.

## Usage

```
DSI-wiki-topics [--instance default-instance] [--layer minified]
DSI-wiki-get <topic> [--instance default-instance] [--layer minified]
DSI-wiki-search <query> [--instance default-instance] [--layer all]
```

- `DSI-wiki-topics` — one topic per line.
- `DSI-wiki-get` — topic content to stdout; exit 1 if not found.
- `DSI-wiki-search` — `<layer>/<topic>: <excerpt>` per hit; exit 1 if no results.
- Unknown instance → exit 2. Layers: raw, documentation, llm, minified, changelog, devlog.

## Session bootstrap

`~/.claude/CLAUDE.md` ("First instinct on any request") uses these for every conversation that
touches a project on this host: `DSI-wiki-topics` to see every `MAIN_*` topic, then
`DSI-wiki-get <relevant topic> --layer brief` (or `documentation`) for whichever is relevant —
no single fixed topic is hardcoded here, relevance is judged per request.
